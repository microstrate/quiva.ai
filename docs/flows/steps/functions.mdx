# Function Step

A Function step runs one of the platform's built-in functions — reading and writing key-value buckets, object storage and streams, plus a handful of transformations such as base64, XML/JSON conversion and Handlebars templating.

---

## Configuration

The editor has four tabs: **General**, **Function**, **Response Map** and **Advanced Settings**.

The **Function** tab holds a required **Function** dropdown listing every function available to your account. Choosing one sets the step's `subject`; the step's payload is then edited against that function's own input schema, either through the generated form or with the **JSON Editor** button.

<Warning>
**The payload is the function's input, with nothing around it.** There is no `{"function": …, "inputs": …}` envelope — the function is named by the dropdown, and the payload is passed straight through.
</Warning>

```json
{ "bucket": "customer-prefs", "key": "$.trigger.user_id", "value": "$.MAP_PREFS" }
```

Every value is JSONPath-resolved before the function runs.

---

## The built-in functions

Pick these by name from the dropdown. The names below are the invocable ones — a few differ from what you might guess from the category.

### Key-value storage

| Function | Required input |
|---|---|
| `create-key-value-bucket` | `bucket` |
| `list-key-value-buckets` | — |
| `put-kv-item` | `bucket`, `key`, `value` |
| `get-kv-bucket-item` | `bucket`, `key` |
| `list-kv-bucket-items` | `bucket` |

### Object storage

| Function | Required input |
|---|---|
| `create-object-store-bucket` | `bucket` |
| `list-object-store-buckets` | — |
| `put-object-by-key` | `bucket`, `name`, `value` |
| `get-object-from-bucket` | `bucket`, `name` |
| `list-object-keys` | `bucket` |

### Streams

| Function | Required input |
|---|---|
| `create-stream` | `name`, `subjects` |
| `list-streams` | — |
| `publish-message-to-stream` | `subject`, `value` |
| `get-item-from-stream` | `stream`, `subject` |
| `search-stream-items` | `stream`, `search`, `limit` |
| `aggregate-stream-items` | `stream`, `subject` |
| `tombstone-message-to-stream` | `subject` |
| `unset-message-to-stream` | `subject` |
| `poison-pill-message-to-stream` | `subject` |

### Transformations and utilities

| Function | Required input |
|---|---|
| `base64-encode` / `base64-decode` | the value itself |
| `JSON-XML` | `json` |
| `XML-JSON` | `xml` |
| `Handlebars Template` | `template`, `variables` |
| `Mapping` | `data`, `path` |
| `Rules` | `rules` |
| `HTTP` | `url`, `method` |
| `SFTP` | `host`, `port`, `username`, `filePath`, `fileContents` |
| `secret-key-get-node` | `key` |
| `function-invoke-node` | `subject`, `payload`, `invocation_type` |
| `Delay` | `ms` |

<Note>
Several of these overlap with dedicated steps — `HTTP`, `Rules`, `Mapping` and `Delay` all have their own step types, which are easier to configure. Reach for the function form of them only when you need it inside a larger function chain.
</Note>

The [Functions reference](/flows/functions/overview) covers each one's full parameter list and output.

## Worked examples

### Store something for later

```json
{ "bucket": "onboarding-state", "key": "$.trigger.account_id", "value": { "stage": "$.CLASSIFY.result", "seen_at": "$.env.run_id" } }
```

### Read it back

```json
{ "bucket": "onboarding-state", "key": "$.trigger.account_id", "json": true }
```

### Publish an event

```json
{ "subject": "orders.created", "value": "$.CREATE_ORDER.data" }
```

### Render a template

```json
{
  "template": "Hi {{name}}, your order {{ref}} is on its way.",
  "variables": { "name": "$.trigger.customer_name", "ref": "$.CREATE_ORDER.data.id" }
}
```

## Response Map

A Function step is one of only two step types whose **Response Map** is applied at run time (the other is a [nested flow](/flows/steps/nested-flows)). It is a JSONPath mapping resolved against the function's result, and what it produces replaces the result under the step ID:

```json
{ "stage": "$.value.stage" }
```

Leave it empty and the function's own result is stored unchanged.

---

## Failure and retries

A function that errors fails the step, and a failed step ends the run. **Advanced Settings** offers the usual controls — `timeout` (honoured on this step type), `attempts` (total, capped at 5), `backoff_ms` (a constant wait), `ignore_response_codes` and `flat_map`.

<Warning>
A Function step must name a function. Saving a flow with one that does not is rejected with `a subject is required for the function`.
</Warning>

<Note>
Editing a flow changes its **draft**. **Publish** to make the change take effect.
</Note>
