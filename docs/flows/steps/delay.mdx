# Delay Step

The Delay step waits, then continues. It has exactly one setting.

<ParamField path="time_ms" type="integer" required>
How long to wait, in milliseconds. The editor labels it **Delay in milliseconds**.
</ParamField>

```json
{ "time_ms": 5000 }
```

There are no units to choose, no "until" time, and no maximum. A value of `0` or less waits not at all.

---

## Two things it does not do

<Warning>
**The delay is not free.** The run holds its place in memory for the whole wait — this is a live run sitting still, not a suspended one that gets picked back up later. There is no pause-and-resume machinery behind it. A delay measured in hours or days ties up the run for that entire period and will not survive a service restart.

For anything longer than a short pause, start a second flow on a [schedule trigger](/flows/triggers/schedule) instead, or use a **Schedule** step to book the follow-up run.
</Warning>

<Warning>
**The wait cannot be computed.** The Delay step reads its payload *before* JSONPath resolution, so `{"time_ms": "$.CONFIG.data.wait"}` never resolves — it fails to decode and errors the step. `time_ms` must be a literal number written into the step.
</Warning>

---

## What it returns

Nothing. `$.my_delay` holds no value; a Delay step exists only for its timing. Steps after it read from whatever ran before it.

---

## Delay compared with the alternatives

| You want | Use |
|---|---|
| A short pause between two calls — rate limiting, letting a write settle | **Delay** |
| A wait of hours or days | A [schedule trigger](/flows/triggers/schedule) on a second flow, or a **Schedule** step |
| To retry a failing call | The step's own **Advanced Settings** — `attempts` and `backoff_ms` |
| To wait for a person | The [Checkpoint step](/flows/steps/human-in-the-loop) |

<Warning>
A Delay step cannot be used to build a retry loop. There is no per-step error branch: the first step to fail cancels the run outright, so no Condition after it — and therefore no Delay after that — is ever reached. Retries belong in **Advanced Settings**, where `attempts` sets the total number of tries (capped at 5) and `backoff_ms` sets a **constant** gap between them.
</Warning>

</Note>
