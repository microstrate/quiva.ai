# Key-Value Storage Functions

A key-value bucket stores small values under string keys. Use it for state a flow needs to keep between runs — a cursor, a counter, a cached lookup, a per-customer setting.

Five functions are available to a [Function step](/flows/steps/functions):

| Function | Does |
|---|---|
| `create-key-value-bucket` | Create a bucket |
| `put-kv-item` | Write one key |
| `get-kv-bucket-item` | Read one key |
| `list-key-value-buckets` | List the account's buckets |
| `list-kv-bucket-items` | List keys and values in a bucket |

Buckets are per-account. There is no delete function — remove a bucket or a key from the platform UI.

<Note>
For anything larger than a small JSON document — a file, a PDF, an export — use [Object Storage](/flows/functions/object-storage) instead.
</Note>

---

## Names and limits

- **Bucket names** must match `[a-zA-Z0-9_-]+`. No dots, no spaces.
- **Keys** must match `[-/_=.a-zA-Z0-9]+` and may not begin or end with a dot. A key built from user input needs sanitising first.
- **`ttl` is in nanoseconds.** It is a Go duration on the wire: one hour is `3600000000000`.
- **`history` defaults to 1 and caps at 64.**

<Warning>
Three of these functions — `get-kv-bucket-item`, `put-kv-item` and `list-kv-bucket-items` — refuse the account's secrets bucket outright and return `{"error": "…"}` explaining why. Read one secret with [`secret-key-get-node`](/flows/functions/utility#secret-key-get-node), or put `SECRET::<name>::` in any node's configuration and let the platform resolve it before the run starts.
</Warning>

## create-key-value-bucket

Creates a bucket. Creating one that already exists returns an error in the body rather than replacing it.

<ParamField path="bucket" type="string" required>
Bucket name. Must be unique in the account and match `[a-zA-Z0-9_-]+`.
</ParamField>

<ParamField path="description" type="string">
Free text shown alongside the bucket.
</ParamField>

<ParamField path="history" type="integer">
Revisions kept per key. Default `1`, maximum `64`.
</ParamField>

<ParamField path="ttl" type="integer">
Key expiry in nanoseconds. Omitted means keys never expire.
</ParamField>

<ParamField path="max_bytes" type="integer">
Maximum total size of the bucket in bytes. Default `-1` (unlimited).
</ParamField>

<ParamField path="max_value_size" type="integer">
Maximum size of a single value in bytes. Default `-1` (unlimited).
</ParamField>

<ParamField path="storage" type="string">
`"file"` or `"memory"`. Default `"file"`. Lower case — a capitalised value is rejected.
</ParamField>

<ParamField path="num_replicas" type="integer">
Copies kept across the cluster. Default `1`, maximum `5`.
</ParamField>

<ParamField path="compression" type="boolean">
Compress the underlying storage.
</ParamField>

<ParamField path="metadata" type="object">
Arbitrary string key-value pairs stored against the bucket.
</ParamField>

**Payload**

```json
{
  "bucket": "run-state",
  "description": "Per-flow cursors",
  "history": 5,
  "ttl": 2592000000000000
}
```

**Returns**

```json
{ "status_code": 200, "body": { "message": "..." } }
```

On failure, `body` carries `error` instead of `message`.

## put-kv-item

Writes a value. Writing an existing key overwrites it; the previous value is kept only if the bucket's `history` is above 1.

<ParamField path="bucket" type="string" required>
Bucket to write into. The bucket must already exist.
</ParamField>

<ParamField path="key" type="string" required>
Key to write. Must match `[-/_=.a-zA-Z0-9]+`.
</ParamField>

<ParamField path="value" type="string | object" required>
The value. An object is stored as JSON; a string is stored as text.
</ParamField>

**Payload**

```json
{
  "bucket": "run-state",
  "key": "sync.orders.cursor",
  "value": { "last_id": "$.GET_ORDERS.body.body.results[-1:].id", "at": "$.env.run_id" }
}
```

**Returns**

```json
{ "status_code": 200, "body": { "message": "..." } }
```

---

## get-kv-bucket-item

Reads one key.

<ParamField path="bucket" type="string" required>
Bucket to read from.
</ParamField>

<ParamField path="key" type="string" required>
Key to read.
</ParamField>

<ParamField path="json" type="boolean">
Parse the stored value as JSON before returning it. Defaults to `false`.
</ParamField>

**Payload**

```json
{ "bucket": "run-state", "key": "sync.orders.cursor", "json": true }
```

**Returns**

```json
{
  "status_code": 200,
  "body": {
    "body": { "key": "sync.orders.cursor", "value": { "last_id": "ord_88" } },
    "metadata": { "Bucket": "run-state" }
  }
}
```

<Warning>
**Set `json: true` whenever you stored an object.** Without it the value is passed through `JSON.stringify`, so a stored object comes back as a JSON *string* and a stored string comes back wrapped in quotes. Downstream steps then see text where they expected a structure.
</Warning>

Reference the value as `$.STEP_ID.body.body.value`.

## list-key-value-buckets

Lists every key-value bucket in the account. Takes no parameters — an empty payload `{}` is correct.

**Returns**

```json
{
  "status_code": 200,
  "body": {
    "body": {
      "results": [
        { "name": "run-state", "description": "Per-flow cursors", "entry_total": 12, "created": 1755000000, "metadata": {} }
      ],
      "results_total": 1
    },
    "metadata": {}
  }
}
```

---

## list-kv-bucket-items

Lists the keys in one bucket, **with their values**. A bucket holding anything sensitive should not be listed from a flow.

<ParamField path="bucket" type="string" required>
Bucket to list.
</ParamField>

<ParamField path="limit" type="integer">
Maximum entries to return.
</ParamField>

<ParamField path="last_sequence" type="integer">
Resume point. Pass the sequence you stopped at to continue a paged listing.
</ParamField>

**Payload**

```json
{ "bucket": "run-state", "limit": 100 }
```

**Returns**

```json
{
  "status_code": 200,
  "body": {
    "body": {
      "results": [{ "key": "sync.orders.cursor", "value": "{\"last_id\":\"ord_88\"}" }],
      "results_total": 1
    },
    "metadata": { "Bucket": "run-state", "Limit": 100 }
  }
}
```

Values in a listing are always strings. Parse them in an [Eval step](/flows/steps/eval) if you need the structure.

---

## Failure

Every function on this page catches its own errors and returns `{"error": "<message>"}`. **That is a successful step** — the run continues and the next step reads an object with an `error` key where it expected data.

If a later step depends on the read succeeding, branch on it:

```json
[
  { "outcome": ["HANDLE_MISS"], "condition": { "operator": "notEmpty", "input": "$.GET_CURSOR.error" } },
  { "outcome": ["USE_CURSOR"] }
]
```

The final cell has no condition, so it always matches. Leave it out and a run where the read succeeded ends with `failed to determine next steps`.

See [Best practices](/flows/best-practices) for what a part-completed run leaves behind.
