# Object Storage Functions

An object bucket stores whole objects under a name. Use it for anything too big for a [key-value bucket](/flows/functions/key-value): a generated document, an inbound attachment, a nightly export.

Five functions are available to a [Function step](/flows/steps/functions):

| Function | Does |
|---|---|
| `create-object-store-bucket` | Create a bucket |
| `put-object-by-key` | Write one object |
| `get-object-from-bucket` | Read one object |
| `list-object-store-buckets` | List the account's buckets |
| `list-object-keys` | List object metadata in a bucket |

Buckets are per-account. There is no delete function — remove a bucket or an object from the platform UI.

<Note>
An object is addressed by **`name`**, not `key`. The two storage families use different parameter names for the same idea.
</Note>

---

## Text in, text out

These functions move text, not binary. `put-object-by-key` stringifies anything that is not already a string and writes the UTF-8 bytes; `get-object-from-bucket` decodes the bytes back as UTF-8. A JSON document, a CSV or an XML payload round-trips exactly. A PDF or an image does not — base64-encode it first with [`base64-encode`](/flows/functions/utility#base64-encode) and decode it on the way out.

Bucket names must match `[a-zA-Z0-9_-]+`.

## create-object-store-bucket

<ParamField path="bucket" type="string" required>
Bucket name. Must be unique in the account and match `[a-zA-Z0-9_-]+`.
</ParamField>

<ParamField path="description" type="string">
Free text shown alongside the bucket.
</ParamField>

<ParamField path="max_bytes" type="integer">
Maximum total size of the bucket in bytes.
</ParamField>

<ParamField path="storage" type="string">
`"file"` or `"memory"`. Default `"file"`. Lower case — a capitalised value is rejected.
</ParamField>

<ParamField path="num_replicas" type="integer">
Copies kept across the cluster. Default `1`, maximum `5`.
</ParamField>

<ParamField path="compression" type="boolean">
Compress the underlying storage.
</ParamField>

<ParamField path="metadata" type="object">
Arbitrary string key-value pairs stored against the bucket.
</ParamField>

**Payload**

```json
{ "bucket": "invoice-exports", "description": "Nightly CSV exports", "max_bytes": 10737418240 }
```

**Returns**

```json
{ "status_code": 200, "body": { "message": "..." } }
```

<Warning>
**The `ttl` field this function's form offers does nothing.** The bucket configuration the platform actually reads names that setting `max_age`, so a `ttl` value is dropped and objects never expire. Delete objects you no longer want, or send `max_age` (in nanoseconds) through the JSON editor.
</Warning>

## put-object-by-key

Writes an object. Writing an existing name replaces it.

<ParamField path="bucket" type="string" required>
Bucket to write into. The bucket must already exist.
</ParamField>

<ParamField path="name" type="string" required>
Object name.
</ParamField>

<ParamField path="value" type="string | object" required>
The content. Anything that is not a string is serialised to JSON first.
</ParamField>

**Payload**

```json
{
  "bucket": "invoice-exports",
  "name": "$.env.run_id",
  "value": "$.BUILD_CSV"
}
```

**Returns**

```json
{ "status_code": 200, "body": {} }
```

A write that fails returns `{"status_code": 500, "body": {"error": "..."}}` — and that is still a successful step. See [Failure](#failure).

---

## get-object-from-bucket

<ParamField path="bucket" type="string" required>
Bucket to read from.
</ParamField>

<ParamField path="name" type="string" required>
Object to read.
</ParamField>

<ParamField path="json" type="boolean">
Parse the decoded text as JSON. Leave it off to get the raw text.
</ParamField>

**Payload**

```json
{ "bucket": "invoice-exports", "name": "export-2026-08-20.json", "json": true }
```

**Returns**

```json
{
  "status_code": 200,
  "body": {
    "body": { "name": "export-2026-08-20.json", "value": { "rows": 412 } },
    "metadata": { "Bucket": "invoice-exports" }
  }
}
```

A missing object returns `{"status_code": 404, "body": {"error": "Not found"}}` — note the shallower shape: there is no `body.body` to read. Test `$.STEP_ID.status_code` before reaching for the value.

If `json` is set and the text is not valid JSON, the raw text is returned rather than an error.

## list-object-store-buckets

Lists every object bucket in the account. Takes no parameters — an empty payload `{}` is correct.

**Returns**

```json
{
  "status_code": 200,
  "body": {
    "body": {
      "results": [
        { "name": "invoice-exports", "description": "Nightly CSV exports", "size": 48211, "created": "2026-08-20T09:14:02Z" }
      ],
      "results_total": 1
    },
    "metadata": {}
  }
}
```

`size` is the bucket's total bytes. The function's declared output schema names this field `entryTotal`; the field on the wire is `size`.

---

## list-object-keys

Lists object **metadata** — never the content.

<ParamField path="bucket" type="string" required>
Bucket to list.
</ParamField>

<ParamField path="limit" type="integer">
Maximum entries in one page. Defaults to `500`.
</ParamField>

<ParamField path="last_sequence" type="integer">
Sequence to start from.
</ParamField>

**Payload**

```json
{ "bucket": "invoice-exports", "limit": 50 }
```

**Returns**

```json
{
  "status_code": 200,
  "body": {
    "body": {
      "results": [
        { "name": "export-2026-08-20.json", "buid": "...", "size": 48211, "chunks": 1, "modified": 1755680042 }
      ],
      "results_total": 1
    },
    "metadata": { "bucket": "invoice-exports", "limit": 50 }
  }
}
```

`results_total` counts the rows **in this page**, not the bucket. When a page is cut short — by your `limit` or by the reply's own size budget — the body also carries `truncated: true` and a `next_cursor` string; send that string back as `cursor` to continue. Treat the cursor as opaque.

To get the content of each object you need a `get-object-from-bucket` call per name.

## Failure

Every function on this page catches its own errors and returns a body containing `error`. **That is a successful step** — the run continues and the next step reads an object with an `error` key where it expected data.

Branch on it before using the result:

```json
[
  { "outcome": ["HANDLE_MISSING"], "condition": { "operator": "!=", "input": ["$.GET_EXPORT.status_code", 200] } },
  { "outcome": ["PARSE_EXPORT"] }
]
```

See [Best practices](/flows/best-practices) for what a part-completed run leaves behind.
