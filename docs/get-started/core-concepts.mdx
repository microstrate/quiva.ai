QuivaWorks is built from a small set of pieces. **Abbie** does the work, **Spaces** hold it, **assistants** are configured for specific jobs, **flows** run on triggers, and the **account** is the boundary everything sits inside.

## Abbie

**Abbie** is the AI coworker and the first thing in the sidebar. You give her a task in conversation and she works through it, using the tools, knowledge and integrations available to your account.

Abbie has five areas:

| Area | What it's for |
|---|---|
| **Home** | "Here's what Abbie's been up to, and what she needs from you" — connections, inbox, reminders and recent conversations |
| **Chat** | Conversations with Abbie |
| **Backlog** | Everything Abbie is tracking for you and your team — multi-step asks she's still working through, and anything parked waiting on you |
| **Logs** | The trace of a run: what she did, in order |
| **Settings** | How Abbie behaves — see below |

**Abbie's settings** cover Rapport (tone and how she works with you), Profile, Skills, Integrations, Model pool, Synapse Memory, Environment, Outreach and Task filing.

<Info>
Pipeline traces and diagnostics are kept for **7 days**, independently of the conversation retention period set for the account.
</Info>

## Assistants

**Assistants** are AI collaborators configured for a specific task, role or domain. Where Abbie is your general coworker, an assistant is shaped for one job and can be shared with the whole team.

### Team vs. personal assistants

<CardGroup cols={2}>
  <Card title="Team assistants" icon="users">
    Available to everyone in the account. Use for standardised workflows, shared tools and company-wide resources.
  </Card>
  <Card title="Personal assistants" icon="user">
    Private to the creator. Use for individual work and experiments.
  </Card>
</CardGroup>

### Configuration layers

Every assistant has two configuration layers that merge at runtime:

- **Team Settings** — shared instructions, knowledge, integrations and context variables
- **Personal Settings** — your own configuration, layered on top without affecting anyone else

**Account-level settings** sit above both and apply to every assistant where you enable them on that assistant:

| Setting | Purpose |
|---|---|
| [**Global Assistant Instructions**](/essentials/account/global-admin-branding-settings#global-assistant-instructions) | Instructions applied automatically to every interaction |
| [**Global Assistant Knowledge**](/essentials/account/global-admin-branding-settings#global-knowledge) | Files available as knowledge to any assistant with the feature enabled |
| **Branding** | App name, favicon and colours for the whole account |

## Flows

**Flows** are automated sequences that run in response to a trigger. A trigger starts the flow, steps do the work, and variable mappings pass data between them.

<CardGroup cols={3}>

## Integrations and MCP

**Model Context Protocol (MCP)** is an open standard that connects assistants and flows to external systems, tools and data sources.

- **Pre-built integrations** — connect to popular tools out of the box
- **Generated integrations** — build an MCP server from an OpenAPI specification for your own internal APIs
- **Enhanced specs** — OpenAPI specs with embedded instructions are supported

### Built-in tools

These tools are available without any integration set-up:

<AccordionGroup>
  <Accordion title="Research">
    - **Web search** — general web results
    - **News search** — recent news results
    - **Web fetch** — retrieve and parse a URL
  </Accordion>
  <Accordion title="Data and computation">
    - **Calculator** — evaluate mathematical expressions
    - **JSON query** — extract values using JSONPath
    - **Regex** — pattern matching
    - **Date/time** — parse and format dates and times
    - **Encoding** — convert data between encodings
    - **Hash** — generate hashes
  </Accordion>
  <Accordion title="People in the loop">
    - **Escalate** — route a request to a person when judgement is needed
  </Accordion>
</AccordionGroup>

Escalations go to the account's **Escalation Responders** if nobody is named on the assistant or flow; if none are set, they go to the account root.

<Card title="Tools and connectors" icon="plug" href="/assistants/tools-and-connectors">
  Connecting assistants to your systems →
</Card>

### Sub-agents

For tool-heavy work, QuivaWorks splits the job across sub-agents so a single context window doesn't have to hold everything. Each sub-agent handles part of the work and results are consolidated back.

## Learning

Assistants improve through **intentional refinement** — you decide when and how they change.

<Steps>
  <Step title="Vote on interactions">
    Thumbs up or down on real conversations to mark what worked
  </Step>
  <Step title="Review insights">
    The Learning tab consolidates that feedback into patterns
  </Step>
  <Step title="Refine behaviour">
    Update instructions, knowledge or settings based on what you've learned
  </Step>
</Steps>

<Info>
Assistants don't change on their own. Nothing is applied until you apply it.
</Info>

## The account

The **account** is the tenancy boundary. Users, Spaces, assistants, flows, credits and storage all belong to one account, and data is isolated per account.

- **Users and roles** — seven roles: root, admin, developer, monitor, billing, collaborator and client. Only root and admin can invite people or change roles.
- **Account settings** — details, branding, global instructions and knowledge, escalation responders, data retention and specialization. Open **Account** in the sidebar (root and admin only).
- **Billing & Plans** — plan, credit balance, usage log and top-ups.
